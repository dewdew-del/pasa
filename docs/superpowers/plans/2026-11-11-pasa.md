# Pasa Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move files both ways between an Android phone and a Windows laptop over the same Wi-Fi/hotspot, with no internet, using a Flutter app and a Tauri app.

**Architecture:** The laptop app (Tauri 2) runs an axum HTTP server on port 47800 and shows a QR with its LAN IPs, port and a saved pairing key. The phone app (Flutter) scans the QR, then uploads files to the laptop (streamed POST) and polls the laptop's outbox every second, downloading anything queued (streamed GET). The laptop UI is plain HTML/JS that gets a transfer-list snapshot from Rust via a Tauri event every 150 ms.

**Tech Stack:** Rust (Tauri 2, axum 0.8, tokio, qrcode, local-ip-address, rand), plain HTML/CSS/JS, Flutter/Dart (mobile_scanner, http, file_picker, shared_preferences, wakelock_plus).

**Spec:** `PLAN.md` (project root). Read it first: it has the locked decisions.

## Global Constraints

- Cost ₱0. No backend, no database, no hosting.
- Laptop: Windows only. Phone: Android 11+ only (`minSdk 30`).
- App id: `com.dewdewdel.pasa`. Product name: `Pasa`.
- Default port `47800`; if busy, bind port `0` (OS picks) and the QR shows the real port.
- QR payload exactly: `pasa://connect?v=1&h=<ip1>,<ip2>&p=<port>&k=<key>&n=<name>`. `key` = 64 lowercase hex chars (32 random bytes). `name` = `COMPUTERNAME` with every char not in `[A-Za-z0-9_-]` replaced by `-`.
- Every `/api/*` request needs `Authorization: Bearer <key>`, else `401`.
- Laptop saves to `<Downloads>\Pasa`; phone saves to `/storage/emulated/0/Download/Pasa`. Both create the folder if missing.
- Name clash: `a.jpg` -> `a (1).jpg` -> `a (2).jpg`. No extension or dotfile (`README`, `.env`): append ` (1)` to the whole name.
- Receivers write to a temp file `.<id>.pasa-part` in the save folder and rename only after all bytes arrived. On any failure or cancel the temp file is deleted.
- Never load a whole file into memory on either side; stream in chunks.
- Theme follows system light/dark. Accent `#1A5FD6 (dark: #5C9CFF)` on both apps.
- UI: `docs/mockup/index.html` is the reference for both apps' layout, copy, states and light/dark colours. Laptop UI may reuse its CSS directly.
- Transfer list order (both apps): live rows (queued/active) on top in send order, then finished rows newest first.
- No-lag rules (both apps, measured in the mockup: 200 rows, 0.3 ms per update): rows keyed by id, built once, then patched (text + progress bar via `transform: scaleX`, Flutter: per-row widget rebuild only); a row moves only when its status changes, as one move, never a full re-sort or `innerHTML` rebuild of the list; progress refresh at most every 150 ms; laptop rows use `content-visibility: auto`; no shadows/blur on resting surfaces.
- Statuses (both apps, serialized snake_case): `queued`, `active`, `done`, `cancelled`, `failed`. Directions: `to_laptop`, `to_phone`.
- Byte formatting (both apps): base 1024, one decimal: `1536` -> `1.5 KB`, `5242880` -> `5.0 MB`; speed adds `/s`. Under 1024: `512 B`.
- Git: repo root is `D:\dev\pasa`. Commits authored by dewdew-del only. No Claude/Anthropic trailers or mentions anywhere in git.
- Dewdew is a Git beginner and wants to confirm each step: after each task, stop, say which files changed and why, and wait for his OK before the next task. Explain git commands in one plain line each.

## Review Focus

1. **Weird or hostile file names from the phone** (`../../x`, `C:\a.exe`, `CON.txt`, `a:b?.txt`, emoji, 300 chars, empty): saved inside `Downloads\Pasa` under a safe name, never outside it. Pinned in Task 2 and Task 5 tests.
2. **Big files (several GB):** axum's default 2 MB body limit must be off for upload, and nothing buffers whole files. Pinned by Task 5 `upload_larger_than_2mb`; Task 8 uses streams only.
3. **Connection drops mid-transfer** (Wi-Fi drops, phone locks, app killed): receiving side deletes the partial file and marks `failed`; nothing half-written stays in Downloads. Pinned by Task 5 `upload_interrupted_leaves_no_file`, `upload_short_body_fails`, Task 8 `download_interrupted_leaves_no_file`. Phone holds a wakelock while its queue is busy (Task 9).
4. **Laptop with several network adapters** (Wi-Fi + hotspot + VirtualBox/VPN): QR lists all private IPv4s, phone tries all in parallel and uses the first that answers. Pinned by Task 3 `is_lan_ipv4` tests and Task 8 `connect_picks_reachable_host`.
5. **Windows Firewall blocks the phone**, especially on a hotspot Windows marks "Public": installer adds an allow rule on all profiles; UI shows a one-line hint. Checked manually in Task 10.

```rust
pub enum Direction { ToLaptop, ToPhone }

pub enum Status { Queued, Active, Done, Cancelled, Failed }
#[derive(Clone, Serialize, Debug)]
pub struct TransferView { pub id: String, pub name: String, pub size: u64, pub bytes: u64,
  pub direction: Direction, pub status: Status, pub speed: u64 /* bytes/s */, pub path: Option<String> }

pub struct Registry { /* Mutex<Vec<Entry>>, dirty: AtomicBool, last_seen: Mutex<Option<Instant>> */ }
impl Registry {
  pub fn new() -> Self;
  pub fn add_incoming(&self, name: &str, size: u64) -> (String, Arc<AtomicBool>); // status Active
  pub fn add_outgoing(&self, path: PathBuf) -> std::io::Result<String>;          // status Queued; name/size from the file
  pub fn queued_outgoing(&self) -> Vec<TransferView>;
  pub fn start_outgoing(&self, id: &str) -> Option<(PathBuf, Arc<AtomicBool>)>;  // Queued -> Active; None otherwise
  pub fn progress(&self, id: &str, bytes: u64);
  pub fn finish(&self, id: &str, status: Status, path: Option<PathBuf>);
  pub fn cancel(&self, id: &str) -> bool;  // sets cancel flag; Queued -> Cancelled right away; false if unknown/finished
  pub fn snapshot(&self) -> Vec<TransferView>; // live first in send order, then finished newest first
  pub fn take_dirty(&self) -> bool;  // true once after any change
  pub fn touch(&self);               // phone was seen now
  pub fn connected(&self) -> bool;   // seen within the last 3 s
}
```

### Task 5: HTTP server (`server.rs`)

**Files:**
- Create: `desktop/src-tauri/src/server.rs` (tests inline, using `tower::ServiceExt::oneshot`)
- Modify: `desktop/src-tauri/src/lib.rs` (`mod server;`)

**Interfaces:**
- Consumes: `files::{sanitize_filename, unique_path}`, `pairing::keys_match`, `transfers::{Registry, Status}`.
- Produces:

```rust
#[derive(Clone)]
pub struct AppState { pub key: Arc<RwLock<String>>, pub registry: Arc<Registry>, pub receive_dir: PathBuf, pub name: String }
pub fn router(state: AppState) -> axum::Router;
pub async fn serve(state: AppState, preferred_port: u16) -> std::io::Result<u16>; // binds 0.0.0.0, spawns, returns real port
```

Routes (all behind an auth middleware that checks `keys_match` and calls `registry.touch()`):

| Route | Success | Errors |
|---|---|---|
| `GET /api/ping` | `200 {"name": <name>, "v": 1}` | `401` |
| `POST /api/upload?name=<pct-encoded>&size=<u64>` body = raw bytes | `201 {"saved_as": "<final file name>"}` | `400` bad query, `410` cancelled on laptop, `500` I/O or short body |
| `GET /api/outbox` | `200 [{"id","name","size"}]` (queued only) | `401` |
| `GET /api/files/{id}` | `200` streamed body, `Content-Length` = size; status Done when the stream ends | `404` unknown, `409` not queued |

Upload algorithm: `create_dir_all(receive_dir)`; `add_incoming(sanitized, size)`; write chunks from `body.into_data_stream()` to `.<id>.pasa-part`, `progress()` per chunk, check the cancel flag per chunk; if bytes written ≠ `size` or any error/cancel → delete temp, `finish(Failed|Cancelled)`, return error; else take a global `static FINALIZE: Mutex<()>`, `unique_path` + rename, `finish(Done, Some(path))`. Upload route uses `DefaultBodyLimit::disable()`.

Download: `start_outgoing(id)`, open the file, wrap `ReaderStream` in a stream that calls `progress()` and stops with an error when the cancel flag is set; on stream end call `finish(Done)`; on error/drop before end `finish(Failed)` (or `Cancelled` if the flag is set). Use a guard struct with `Drop` to catch a dropped stream.

### Task 8: Phone API client (`api.dart`)

**Interfaces:**
- Consumes: `LaptopInfo`, `uniqueName`.
- Produces:

```dart
class OutboxItem { final String id; final String name; final int size; }
class PasaApi {
  PasaApi(this.baseUrl, this.key);                 // baseUrl like "http://192.168.1.5:47800"
  final String baseUrl; final String key;
  static Future<PasaApi?> connect(LaptopInfo info, {Duration timeout = const Duration(seconds: 2)});
      // pings every host in parallel; first 200 wins; null if none
  Future<List<OutboxItem>> outbox();
  Future<void> upload(File file, {required void Function(int sent) onProgress, required Future<void> abort});
      // AbortableStreamedRequest, body = file.openRead() counted chunk by chunk; Content-Length = file length;
      // query name = basename (Uri-encoded), size = file length; throws PasaException unless 201
  Future<File> download(OutboxItem item, Directory dir, {required void Function(int got) onProgress, required Future<void> abort});
      // streams to dir/.<id>.pasa-part; on success rename to uniqueName(dir, basename(item.name)); on any error/abort delete temp and rethrow
}
class PasaException implements Exception { final String message; }
```

**Interfaces:**
- Consumes: `PasaApi`, `OutboxItem`, `LaptopInfo`, `saveLaptop/loadLaptop/forgetLaptop`, `receiveDir`, `formatBytes/formatSpeed`.
- Produces:

```dart
enum Dir { toLaptop, toPhone }
enum TStatus { queued, active, done, cancelled, failed }
class Transfer { final String id; final String name; final int size; final Dir dir;
  int bytes; TStatus status; DateTime? startedAt; int get speed; /* bytes/s, 0 before 0.2 s */ }
class TransferQueue extends ChangeNotifier {
  TransferQueue(this.api, {required this.saveDir, this.pollEvery = const Duration(seconds: 1)});
  List<Transfer> get items;          // live first in send order, then finished newest first
  bool get connected;                // last successful poll within 3 s
  void start();                      // begins outbox polling
  void addUploads(List<File> files); // queued, ids are local
  void cancel(String id);            // queued -> cancelled; active -> completes the abort future
  @override void dispose();          // stops polling, aborts active
}
```

Rules: one transfer runs at a time, FIFO across both directions. Each poll adds outbox items whose id isn't already in `items`. Wakelock on (`WakelockPlus.enable`) while anything is queued/active, off when idle. Failed polls only flip `connected`; they never fail transfers.

Always a "Scan QR" button opening a full-screen `MobileScanner`; on a code, `parseQr` (non-Pasa codes show "That's not a Pasa code" and keep scanning), `connect`, `saveLaptop`, go to `TransferScreen`.
- `TransferScreen`: app bar "Connected to <name>" + dot (green when `connected`); a large "Send files" button (`FilePicker.platform.pickFiles(allowMultiple: true)` -> `addUploads`); list rows like the laptop (arrow, name, `bytes / size`, progress bar, speed, ✕ while queued/active, status text after).
